## Changes

- Add release assets for the standalone display installer, its SHA-256 checksum,
  and a manifest that identifies the release and tested commit.
- Add display configuration version recording, prior-install checks and targeted
  migration, read-only preview, and JSON results for host tools.
- Start the display service from Labwc login and preserve the browser profile
  and pairing during updates. Unchanged healthy displays are left running.
- Keep manual and automated display setup on the same installer. Host tools can
  pin a stable release or resolve latest stable during preview and retain that
  exact version for apply.

## Setup changes

Download `install-display.sh`, `install-display.sh.sha256`, and
`display-installer.json` from this release. Verify the checksum and run the
installer as the signed-in graphical account. See
[`display-automation.md`](../display-automation.md) for preview, migration,
service environment, and automation details.

Earlier releases do not contain these display assets. The installer requires
an existing graphical desktop, Chromium or noninteractive package-install
access, and a user systemd manager. Live startup validation covers Debian 13
ARM64 with Labwc, including a full reboot and preserved pairing.

Display setup is separate from application-server deployment. The workflow
publishes application images for this release but does not update any host.

## Database migrations

None.

## Rollback

Direct rollback supported to application image 0.3.1. This release does not
change the database or application schema.

Display configuration has a separate format version, currently `1`. Release
0.3.1 has no installer assets for an automated display rollback. Retain the
previous reviewed installer and desktop/service configuration when migrating,
and preserve the browser profile when restoring an older display setup.
