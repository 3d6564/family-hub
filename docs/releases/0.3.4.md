# Family Hub 0.3.4

## Changes

- Keep Calendar and Routines separate while improving the existing settings tabs.
- Wrap tabs on narrow screens and use the available section width.
- Move screen revocation into Screens and separate account, maintenance, and
  restoration controls within Access.
- Use explicit saving, including token visibility. Show draft, saving, saved,
  and error states. Preserve drafts during unrelated refreshes and failed saves.
- Warn before discarding settings edits and prevent duplicate submissions.
- Isolate section loading failures and provide retry controls.
- Show weather/calendar connection status and last successful updates when
  known. Connection-attempt history resets on service restart.
- Keep saved weather keys on the server. Replacement key fields remain blank
  unless the user enters a new key. Settings API responses no longer contain
  saved keys; they report whether each provider has a key.
- Confirm calendar deletion, screen revocation, and household restoration.
- Show only the installed application version, without host-specific deployment
  guidance. Remove planned integration cards from working settings.

## Setup changes

Use image `ghcr.io/3d6564/family-hub:0.3.4`. Pull and replace the application
container with your existing deployment tool. Preserve environment settings and
the data volume. Reload open browsers after updating.

No dependency changes. Optional browser tests use an existing Chromium binary
through `FAMILY_HUB_TEST_BROWSER`; no new package is required.

## Database migrations

None since 0.3.3. Existing settings and provider keys are retained.

## Rollback

Direct rollback supported to 0.3.3. No schema change is required. Reload browsers
after rollback so the settings interface matches the server API.

## Verification

- `npm run check`
- `npm test`, including Chromium settings checks at 390, 760, 1024, 1440,
  and 1920 pixel widths in the local test container
- AMD64 image smoke test (release workflow)
- ARM64 image smoke test (release workflow)

Live-provider and physical-display checks are not included. Broader settings
navigation and organization changes remain deferred.
