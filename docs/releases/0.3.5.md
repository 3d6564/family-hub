# Family Hub 0.3.5

## Changes

- Add **Reconnect** to each registered screen in Settings > Screens. An adult
  enters the code shown at the screen's new browser address.
- Preserve the screen's record, name, creation date, and reported dimensions.
  A valid new report updates dimensions on the same record.
- Keep the old credential valid until the new browser claims its approved
  connection, then replace the credential and close old screen event streams.
- Reject expired, revoked, cross-household, or superseded reconnect attempts.
  Failed attempts do not silently create another screen.
- Add a short README guide and kiosk command for changing the Hub address.
  The existing installer preserves the browser profile when updating its URL.

## Setup changes

Use image `ghcr.io/3d6564/family-hub:0.3.5` with your existing environment and
data volume. Deploy this release before starting an address change. Reload
browser tabs after deployment. No dependency or kiosk-installer changes.

For an address change, first save a backup and verify the new HTTPS address and
certificate from the Pi. Set `SITE_URL`, update the kiosk using the README
command, then sign in at the new address and reconnect the existing screen.
Changing `SITE_URL` does not change the kiosk's saved address. The old HTTP
address can stop accepting changes when HTTPS and origin settings change, even
while the old credential has not yet been revoked.

## Database migrations

Startup applies `025_screen_reconnect.sql`. It adds two optional pairing fields
for the selected screen and a snapshot of its credential hash. Existing screen
records are unchanged. Save a current backup before deployment.

## Rollback

Direct rollback supported to 0.3.4. Complete pending reconnects, or let their
10-minute codes expire without starting new attempts, before rollback. Version
0.3.4 does not understand reconnect approvals and could treat a pending approval
as a new screen. Reload browsers after rollback so the UI matches the API.

## Verification

- `npm run check`
- `npm test`, including local Chromium checks at phone and desktop widths
- Kiosk address-update tests confirm the startup URL changes and profile remains
- AMD64 image smoke test (release workflow)
- ARM64 image smoke test (release workflow)

The live environment, Raspberry Pi, DNS, proxy, and laptop migration are left
unchanged. Actual HTTPS certificate trust and network reachability must be
checked on those devices before migration.
