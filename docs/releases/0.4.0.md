# Family Hub 0.4.0

## Changes

- Add a Lists tab for one selected AnyList grocery or household list. AnyList
  remains the source of truth. This is an experimental, unofficial connection;
  account compatibility is not guaranteed.
- Adults manage the connection. Authenticated household members and paired
  displays can add and check/uncheck items. Only adults can delete completed
  items. Existing request-verification and household isolation checks remain.
- Encrypt provider tokens at rest, do not retain the account password, and keep
  cached list data available during provider failures.
- Preserve quantity units and allow list selection to be saved while disabled
  without contacting AnyList. Switching lists clears the previous list cache.
- Move main navigation to a left sidebar on wide screens; retain bottom
  navigation on phones. Keep the header and calendar within narrower viewports.
- Add a Node.js 22 development container and optional Chromium test image.

## Setup changes

Use image `ghcr.io/3d6564/family-hub:0.4.0`. Save a backup before updating and
preserve all existing environment values and the `/data` volume. No kiosk
installer changes are required. Reload open browsers after deployment.

AnyList is optional. To connect it, set `FAMILY_HUB_INTEGRATION_KEY` to a separate
random 32-byte key encoded as 64 hexadecimal characters. Keep this key private,
separate from the database, and available for recovery. Existing calendar and
task features work without it. Never paste the key into source or an issue.

For Portainer, add the key as a private stack environment value and ensure the
service's `environment` section includes:

```yaml
FAMILY_HUB_INTEGRATION_KEY: ${FAMILY_HUB_INTEGRATION_KEY:-}
```

Set `FAMILY_HUB_VERSION=0.4.0` (or use the image tag above), pull the new image,
and redeploy only the application container. Do not recreate or remove the
household data volume. After health succeeds, an adult can open
**Settings → Integrations → AnyList**, connect, select a list, and enable it.
Use HTTPS before entering account credentials.

See [AnyList setup and limits](../anylist.md) and the
[Portainer guide](../portainer.md). The new application dependency is pinned
`protobufjs` 8.8.1; Home Assistant and the old `anylist` package are not required.

## Database migrations

Migration `026_anylist.sql` adds an independent, household-scoped connection
and selected-list cache table. Existing household tables and records are not
rewritten. Cached items are private data and are included in database backups.
Provider tokens in backups are encrypted; the server encryption key is not
included. A restored connection needs the original key or adult reconnection.

## Rollback

Direct rollback supported to 0.3.6. The migration only adds a table that 0.3.6
ignores. Select `ghcr.io/3d6564/family-hub:0.3.6` with the same environment and
volume, then reload browsers. AnyList and Lists will not be available there.
Keep the key securely if you plan to return to 0.4.0. Older backups can still
contain the connection and cached data even after it is disconnected.

Save a backup before updating. For upgrades from older versions, review each
intervening release. See the [recovery guide](../update-and-recovery.md).

## Verification

- `npm run check` through the Node.js 22 development container.
- `npm test` with Chromium: 69 tests, including quantity units, disabled list
  selection, cache handling, permissions, token refresh, and household isolation.
- Browser checks cover phone, tablet, and desktop widths from 390 to 1920 pixels.
- Direct rollback smoke test: 0.3.6 opens the migrated synthetic database and
  serves readiness and the authenticated dashboard successfully.
- AMD64 and ARM64 image builds and smoke tests are required by the release
  workflow before publication.
- Display installer assets are packaged and verified by the release workflow.

Live AnyList account compatibility and Portainer operation have not been
verified by the agent. The unofficial API can change. Concurrent changes on
another device can race with adult deletion; no provider-side conditional
delete has been verified. Existing dependency advisories for `body-parser`
(high) and `qs` (moderate) remain outside this feature change. Release
publication does not update a household deployment.
