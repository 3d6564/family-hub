# Family Hub 0.4.1

## Changes

- Narrow the wide-screen sidebar to 88px.
- Add a shared on-screen keyboard for paired-display text fields, excluding
  passwords. Personal devices keep their native keyboard.
- Return paired displays from Lists to Calendar after 60 seconds without
  activity. Wait for active saves and retain unfinished drafts until reload.
- Select multiple lists from one AnyList account. Show up to three together
  on wide screens, with Settings-style tabs for larger selections and phones.
- Keep writes scoped to the selected list and retain each list's saved items
  when another list becomes unavailable. Adult-only connection and deletion
  permissions remain unchanged.

## Setup changes

Use `ghcr.io/3d6564/family-hub:0.4.1`. Save a backup before updating. Preserve
the existing data volume, environment values, and `FAMILY_HUB_INTEGRATION_KEY`.
For Portainer, set `FAMILY_HUB_VERSION=0.4.1`, pull the image, and redeploy
only the application container. Reload open browsers after deployment.
No kiosk installer changes are required. Publication does not update a host.

## Database migrations

Migration `027_anylist_multiple_lists.sql` adds household-scoped selected-list
storage. It preserves the existing selection, cached items, fetch time, and
disabled state. Other household records are unchanged.

## Rollback

Backup restore required to 0.4.0. Restore the pre-update backup before running
the previous image. Version 0.4.0 does not maintain the new multi-list storage;
running it against that storage could leave stale selections on re-upgrade.
See the [recovery guide](../update-and-recovery.md).

## Verification

- `npm run check` through the Node.js 22 development container.
- `npm test` with Chromium: 76 passing tests, including multi-list migration,
  write isolation, permissions, keyboard input, idle return, and draft retention.
- Browser layout checks cover phone, tablet, and desktop widths, 390–1920px.
- User tested the isolated local build and approved release.
- AMD64 and ARM64 image builds, smoke tests, and display installer asset checks
  must pass in the release workflow before publication.

Live AnyList compatibility remains experimental. Existing dependency advisories
reported during the local build (one high and one moderate) remain deferred;
no dependencies changed in this release. Physical kiosk testing remains limited
to user testing; automated browser checks use sample data.
