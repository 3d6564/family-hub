# Family Hub 0.5.2

## Changes

- Rebuild Settings with icon navigation, aligned setting rows, and phone layouts.
- Manage saved calendars and Google account connections separately under
  Settings > Calendars. Add and edit calendars on the page with Back controls.
- Make existing private HTTPS iCal support easier to find, with instructions for
  Google Calendar secret feed URLs. No Google OAuth is needed for these feeds.
- Give safe recovery instructions for known Google authorization failures without
  exposing provider responses, tokens, or credentials. The live OAuth issue
  remains under investigation in issue #49.
- Share control styling across Lists, chores, routines, and reminder editors,
  while retaining household palettes, calendar colors, and token coins.
- Preserve failed edits, guard unsaved changes, prevent duplicate form saves,
  and restore task checkboxes when completion requests fail.
- Fix the calendar settings lookup used when refreshing after a task save.
- Align setup guides and the integration roadmap with the current interface.

## Setup changes

Use `ghcr.io/3d6564/family-hub:0.5.2`. Save a backup before updating. Preserve
all existing environment values, the data volume, and
`FAMILY_HUB_INTEGRATION_KEY`. For Portainer, set `FAMILY_HUB_VERSION=0.5.2`,
pull the image, and redeploy only the application container. Reload open
browsers after replacement. No kiosk installer changes are required.
Publication does not update a host.

Private feed URLs are sensitive and remain part of the database and backups.
Do not make a Google calendar public to use its secret iCal URL.

## Database migrations

None. No schema or dependency changes.

## Rollback

Direct rollback to 0.5.1 is supported. Restore the 0.5.1 image with the same
environment values, integration key, and data volume, then reload browsers.
The previous interface calls iCal feeds public, but saved private HTTPS feed
URLs continue to use the existing feed storage. See the
[recovery guide](../update-and-recovery.md).

## Verification

- Run `npm run check` and `npm test` through the Node.js 22 development container.
- Include Chromium browser checks for phone and desktop layouts, dark mode,
  paired-display permissions, form failures, draft guards, and focus restoration.
- AMD64 and ARM64 builds, smoke tests, and display installer asset checks must
  pass in the release workflow before publication.
- Live Google Calendar account behavior and physical wall-display interaction
  remain unverified. The release improves diagnostics; it does not establish
  the cause of the reported OAuth failure.
