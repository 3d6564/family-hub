# Family Hub 0.5.3

## Changes

- Let an adult add or subtract a child's available token balance in $0.25
  increments. A reason is required. The chore-earned total stays unchanged, and
  the available balance cannot go negative.
- Let an adult reverse a withdrawal or manual adjustment once. The original line
  stays visible and is marked reversed.
- When a chore assigned to anyone has a reward, ask which child earned it before
  saving the completion. The chore stays available to anyone. Unchecking removes
  the reward when it has not been withdrawn.
- Keep token corrections away from paired displays. Displays can still dispense
  tokens and complete chores.

## Setup changes

Use `ghcr.io/3d6564/family-hub:0.5.3`. Save a backup before updating. Preserve
all existing environment values, the data volume, and
`FAMILY_HUB_INTEGRATION_KEY`. For Portainer, set `FAMILY_HUB_VERSION=0.5.3`,
pull the image, and redeploy only the application container. Reload open
browsers after replacement. No kiosk installer changes are required.
Publication does not update a host.

## Database migrations

Startup applies `030_token_adjustments.sql`. It adds correction history for
manual balance changes and reversals. It does not change existing earnings or
withdrawals.

## Rollback

Direct rollback to 0.5.2 is supported. Restore the 0.5.2 image with the same
environment values, integration key, and data volume, then reload browsers.
Version 0.5.2 ignores token adjustment rows, so an available balance can differ
until 0.5.3 is restored. See the [recovery guide](../update-and-recovery.md).

## Verification

  container, including adult correction and unassigned-reward tests.
- The ledger layout and reward dialog were not checked visually in a browser.
  Narrow and wide layout rules are in place.
- AMD64 and ARM64 builds, smoke tests, and display installer asset checks must
  pass in the release workflow before publication.
