# Family Hub 0.5.5

## Changes

- Keep calendar chore and routine checkboxes in place while a completion saves.
  A save no longer adds a status row, disables the box, or rebuilds the widget.
- Remove the separator lines between chore and routine rows in the calendar
  sidebar. Routine period dividers remain. The chores and routines pages are
  unchanged.
- Show a fixed recovery reason when Google Calendar rejects a refresh or a new
  connection. Calendar warnings, the settings status, and the connect popup use
  the same reason. A short OAuth error code is included when Google sends one.
  Provider descriptions, tokens, and secrets are not shown.
- Document Google Testing-mode refresh expiry, the private iCal alternative, and
  the recovery messages.

## Setup changes

Use `ghcr.io/3d6564/family-hub:0.5.5`. Save a backup before updating. Preserve
all existing environment values, the data volume, and
`FAMILY_HUB_INTEGRATION_KEY`. For Portainer, set `FAMILY_HUB_VERSION=0.5.5`,
pull the image, and redeploy only the application container. Reload open
browsers after replacement. No kiosk installer changes are required.
Publication does not update a host.

## Database migrations

None. No schema or dependency changes.

## Rollback

Direct rollback to 0.5.4 is supported. Restore the 0.5.4 image with the same
environment values, integration key, and data volume, then reload browsers.
See the [recovery guide](../update-and-recovery.md).

## Verification

- `npm run check` and `npm test` passed through the Node.js 22 development
  container with browser tests enabled.
- Calendar sidebar screenshots were reviewed at 1440x1000 and 1280x720. The
  phone calendar view hides these lists.
- AMD64 and ARM64 builds, smoke tests, and display installer asset checks must
  pass in the release workflow before publication.
- Live Google Calendar behavior is not verified. After deployment, use Test
  connection and keep the shown recovery message if updates still fail.
- Production deployment remains a separate host operation.
